# Stream API
## Удачная аналогия для Stream-а и новый уровень абстракции
В качестве примера из практики можно привести Unix/Linux, в которых многие программы читают данные из стандартного потока ввода, производят какие-либо действия и записывают результаты действий в стандартный поток вывода.<br/>
Командная строка Unix предоставляет возможность связывать программы цепочкой с помощью символа конвейера (`|`), например:
```bash
cat file1 file2 | tr "[A-Z]" "[a-z]" | sort | tail -3
```

Главный вывод из этого: теперь появляется возможность создавать программы на Java8 на более высоком уровне абстракции<br/>

## Внешние и внутренние итерации
При использовании коллекции приходится организовывать цикл самостоятельно: пройтись по всем элементам, обрабатывая их по почереди в цикле `for-each`. Это _внешняя итерация_ (_external iteration_)<br/>
При использовании Stream API думать у циклах не нужно. Вся обработка происходит внутри библиотеки. Это - _внутренняя итерация_ (_internal iteration_)<br/>

## Проблемы при parallel
### Проблема №1
```java
List<Integer> numbers = IntStream.rangeClosed(1, 10000).boxed().collect(Collectors.toList());
List<Integer> result = new ArrayList<>(); // НЕ потокобезопасный!

numbers.parallelStream()
       .filter(x -> x % 2 == 0)
       .forEach(result::add); // ❌ ОПАСНО! add() не синхронизирован, будут коллизии и потеря элементов
```
Пофиксить можно так
```java
List<Integer> result = numbers.parallelStream()
                              .filter(x -> x % 2 == 0)
                              .collect(Collectors.toList()); // ✅ Безопасно!
```
или так
```java
List<Integer> result = new CopyOnWriteArrayList<>();
numbers.parallelStream().forEach(result::add); // ✅ Безопасно (но медленно)
```

#### Проблема №2
Если операции простые и мало элементов, то накладные расходы превышут выигрыш

#### Проблема №3
Все parallelStream() по умолчанию используют общий пул ForkJoinPool.commonPool(), который по умолчанию содержит Runtime.getRuntime().availableProcessors() - 1 потоков\
Проблема: Если вы запустите внутри parallelStream() тяжелую синхронную операцию (например, запрос в БД или HTTP-вызов), этот пул заблокируется. Все остальные parallelStream в приложении будут стоять в очереди, и приложение может зависнуть.
