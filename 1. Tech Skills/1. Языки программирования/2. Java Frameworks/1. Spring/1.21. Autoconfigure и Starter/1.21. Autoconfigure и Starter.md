## SpringBoot Autoconfigure
Spring Boot смотрит, какие библиотеки вы подключили, и сам решает, какие бины создать и как их настроить.

- Подключили `spring-boot-starter-web`? → Автоматически создаст `DispatcherServlet`, `Tomcat`, `ObjectMapper`.
- Подключили `spring-boot-starter-data-jpa`? → Автоматически создаст `DataSource`, `EntityManagerFactory`, `TransactionManager`.
- Подключили H2 в зависимостях? → Сама создаст in-memory базу данных.

Это работает благодаря условной конфигурации (`@Conditional`)

За это отвечает аннотация `@EnableAutoConfiguration`, которая входит в `@SpringBootApplication`.\
- Когда стартует приложение, `@EnableAutoConfiguration` подсказывает Spring искать
    - в classpath файл `META-INF/spring.factories` (для старых версий)
    - или `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` (начиная с Spring Boot 2.7+)
- В этом файле перечислены все классы автоконфигурации, которые нужно попробовать загрузить (около 150-200)\
- Каждый такой класс помечен условными аннотациями (`@ConditionalOn`...). Spring проверяет эти условия и, если они выполняются, активирует конфигурацию. Если нет — просто пропускает

```java
@Configuration(proxyBeanMethods = false)
@ConditionalOnClass({ DataSource.class, EmbeddedDatabaseType.class })
@EnableConfigurationProperties(DataSourceProperties.class)
public class DataSourceAutoConfiguration {

    @Configuration(proxyBeanMethods = false)
    @ConditionalOnMissingBean(DataSource.class)
    @ConditionalOnProperty(name = "spring.datasource.url")
    static class EmbeddedConfiguration {

        @Bean
        public DataSource dataSource(DataSourceProperties properties) {
            // Создает HikariCP или Tomcat JDBC DataSource
            return properties.initializeDataSourceBuilder().build();
        }
    }
}
```
Тут
- `@ConditionalOnClass({ DataSource.class, EmbeddedDatabaseType.class })` — Если есть Datasource или Embeded DB, активируемся
- `@ConditionalOnMissingBean(DataSource.class)` — Если разработчик сам не создал свой `DataSource`, Spring создаст его сам. Если разработчик создал — Spring уважает его выбор и не переопределяет бин.

## Как написать свой стартер
Нужно создать класс с конфигурацией
```java
@AutoConfiguration
@ConditionalOnClass(MyApiClient.class)
@EnableConfigurationProperties(MyApiProperties.class)
public class MyApiAutoConfiguration {

  @Bean
  @ConditionalOnMissingBean
  public MyApiClient myApiClient(MyApiProperties properties) {
    return new MyApiClient(properties.getUrl(), properties.getApiKey());
  }
}
```
Нужно сделать класс для свойств, если надо
```java
@ConfigurationProperties(prefix = "myapi")
public class MyApiProperties {
  private String url;
  private String apiKey;
  // getters / setters
}
```
Нужно зарегистрировать автоконфигурацию
- `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` (Spring Boot 2.7+)\
```txt
com.example.MyApiAutoConfiguration
```
- `META-INF/spring.factories` (для старых версий)\
```txt
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
com.example.MyApiAutoConfiguration 
```
